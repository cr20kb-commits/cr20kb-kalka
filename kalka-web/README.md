# CR20KB «Калька Web» 0.2.0 preview

Изолированный проверочный вариант, **не готовый к полноценному выпуску**. Пользовательские файлы обрабатываются в браузере. Для сравнения нужна ручная проверка совмещения; результат не заменяет инженерную проверку.

## Первый просмотр

Из этого каталога с Node.js 24 выполните:

```powershell
node build.mjs
node serve.mjs
```

Откройте `http://127.0.0.1:4173/kalka-web/`. Сервер нужен только для локальной проверки разработчиком. Для конечных пользователей разместите содержимое `dist/` целиком на HTTPS в отдельном каталоге, например `https://example.org/kalka-web/`. Настройте MIME: `.mjs` и `.js` — JavaScript, `.wasm` — `application/wasm`, `.webmanifest` — `application/manifest+json`, `.html` — `text/html`; сохраняйте остальные файлы и каталоги. Не используйте открытие `index.html` двойным щелчком. После загрузки дождитесь индикатора готовности: он означает, что текущая страница контролируется Service Worker и обязательные ресурсы присутствуют в его кэше. Доступность установки зависит от браузера; вкладка работает без установки. После очистки хранилища для подготовки потребуется сеть. Обновление не принудительно перезагружает открытые страницы; для каждого нового выпуска меняйте имя кэша в `src/sw.js`.

Первые три действия: (1) откройте два чертежа и совместите их вручную; (2) нажмите «Сравнить A / B», изучите области и экспортируйте PNG; (3) сохраните проект локально, экспортируйте `.kalkaweb`, закройте вкладку и проверьте восстановление без сети. Состояние загрузки означает передачу браузеру, а не гарантию записи на диск. Важные проекты экспортируйте отдельно; постоянное хранилище браузера не гарантировано.

## Что реализовано и ограничения

- До 10 PDF/JPG/PNG; один слой — одна страница. PDF-превью ограничено 4 Мп на слой, все превью — 24 Мп; исходный PNG/JPEG — до 8 Мп. Исходники ограничены 40 МиБ на файл и 80 МиБ всего. Фактический пик памяти не измерялся; PDF.js и браузер могут потребовать дополнительную память.
- Сравнение A/B и PNG имеют независимые множители 1×, 2×, 2,5× относительно размеров превью. Для PDF исходная страница растеризуется заново участками 1024 × 1024, а не увеличивается превью; при сравнении обрабатывается только выбранная пара. Для PNG/JPG увеличение размера не создаёт дополнительных деталей. При сравнении показаны размеры и приблизительный DPI каждого PDF; ниже 100 DPI отображается предупреждение. 100 DPI не гарантирует достаточной точности: выбирайте разрешение по размеру нужных деталей.
- На отдельные сравнение и PNG действует предел 25 Мп и 10 000 пикселей на сторону. При превышении операция отказывается без частичного результата; на некоторых устройствах память может закончиться раньше. Доступны статус обработки по участкам и отмена: растеризация PDF отменяется, Worker завершается; уже начатое кодирование PNG браузером нельзя прервать до возврата `toBlob`. При отмене результат сравнения не считается полученным. В PDF, содержащих крупные встроенные изображения или сложные данные, декодер может расходовать дополнительную память вне плиточного бюджета.
- Перенесены пороговая маска, группировка, ограниченная компенсация целочисленного сдвига до 2 пикселей сравнения и проверка дробной фазы из `kalka_compare.py`. Коррекция применяется только при достаточно сильных распределённых признаках и показана в пикселях системы превью; разреженные или неоднозначные листы остаются без компенсации. Коррекция при повороте/масштабе ограничена целыми пикселями. Проверяйте совмещение вручную: алгоритм может ошибаться или не компенсировать сдвиг. Это самостоятельный перенос, не полный эквивалент Windows.
- После сравнения A отображается синим, B красным, общие штрихи фиолетовыми. Маркеры включаются отдельно и привязаны к координатам листа; при другом масштабе PNG его исходники обрабатываются заново с сохранением рассчитанной коррекции. Порог различия 56 и JPEG-артефакты могут как скрыть слабые отличия, так и создать ложные области. Отсутствие областей не гарантирует совпадение.
- Данные исходников и новые настройки качества/A/B находятся внутри версии 1 JSON `.kalkaweb`; прежние Web-проекты без настроек открываются с настройками по умолчанию. Windows `.kalka` несовместимы. Формат ограничен по размеру, вход проверяется, исполняемый код и архивы не используются. Исходные файлы не изменяются.
- Пока не полностью локализованы сообщения исключений PDF.js и окно авторства; Chrome-снимок телефона является эмуляцией, не проверкой Android. Подробные результаты и выпускные блокеры — в `TEST_REPORT.md`.

## Проверки разработчика

```powershell
node --test tests/*.test.mjs
node build.mjs
$env:NODE_PATH = '<каталог с playwright и pdf-lib>'
node tests/browser.cjs
```

`tests/browser.cjs` использует Playwright 1.62.1, pdf-lib 1.17.1 и локальный Chrome; он запускает временный сервер только на loopback. Переменная `CHROME_PATH` позволяет указать Chrome. `tests/high-resolution.cjs` дополнительно использует sharp 0.35.5 и создаёт синтетический A0. `tests/real-pair.cjs` и `tests/real-shift.cjs` используют sharp и локальные пути исходников; личные файлы и результаты `test-output/` в Git не входят. Зависимости тестов не нужны конечному пользователю и не входят в dist; продуктовые ресурсы PDF.js 5.6.205 закреплены в `src/vendor/pdfjs`. `package-lock.json` фиксирует пакет сборки без npm-зависимостей.
